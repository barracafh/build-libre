# Data

Snapshot of the XV legislature (Pleno votes, sessions and interventions) and of the general-election
data per province, taken from [Escaño Abierto](https://github.com/jorgegarcelan/escano-abierto) (code
MIT, data CC BY 4.0), which builds them from the
[Congreso de los Diputados open data](https://www.congreso.es/es/datos-abiertos), the Ministerio del
Interior results and the INE. Generated by `pnpm data:fetch` (`scripts/fetch-data.ts`) from the commit
pinned in `source.json`; never edit these files by hand.

| File | Content |
| --- | --- |
| `votaciones/YYYY-MM.json` | The `votaciones` array of upstream `site/datos/YYYY-MM.json`, one vote per line, records unchanged. A month with no Pleno votes is an empty array; a month missing upstream has no file (listed in `source.json`). |
| `sesiones/YYYY-MM.json` | The `sesiones` array of the same upstream file: one session (a Diario de Sesiones of the Pleno or of a committee) per line. |
| `intervenciones/YYYY-MM.json` | The `intervenciones` array of the same upstream file: one speech per line, filed under the month of its session. |
| `items/YYYY-MM.json` | The `items` array of the same upstream file: the agenda-item texts that `intervenciones` point to by position. |
| `indice.json` | Upstream `site/datos/indice.json`, unchanged. Its `diputados` array is the key to `v` (below). |
| `diputados.json` | Upstream `data/diputados.json`, unchanged: one entry per deputy name (`circunscripcion`, `formacion`, `alta`, `baja`, `biografia`). |
| `hemiciclo.json` | Upstream `data/hemiciclo.json`, unchanged: seat plan (`escanos` by deputy name with `x`, `y`, `codigo`; `gobierno`; `ancho`, `alto`). |
| `elecciones/resultados-2023.json` | 2023 general election (23 July 2023) results per province. See [Elections](#elections). |
| `elecciones/escanos-2026.json` | Seats each province elects on 29 November 2026. See [Elections](#elections). |
| `elecciones/territorios.json` | Upstream `data/geografia/territorios.json`, unchanged: names and INE codes of provinces and autonomous communities. |
| `temas.json` | Derived, not upstream: for each of the fixed topics, its votes grouped into initiatives (same `exp`, or same day and `texto`), with main votes, amendment votes apart, sessions and Diario links. Written by `scripts/temas.ts` from `datosTemas()` in `src/lib/datos.ts`; types there. Initiatives without a topic are only counted (`sinTema`). |
| `source.json` | Repository, pinned commit, fetch date, licences, missing months, and every file with its upstream path and record count. |

Everything is limited to the XV legislature (constituted on 17 August 2023): `pnpm data:fetch` fails
if a session is dated earlier or an intervention points to a session outside its month. In this
snapshot: 2,185 votes (2023-09-19 to 2026-10-02), 832 sessions (2023-08-17 to 2026-10-02; 235 of
them Pleno), 28,200 interventions (same dates, by session) and 4,170 agenda items.

## Vote record

Main fields: `id` (session-vote), `fecha`, `tipo`, `titulo`, `texto`, `proponente`, `exp`,
`si`/`no`/`abst`/`novota` totals, `grupos` (majority position per parliamentary group: `S` yes, `N` no,
`A` abstention, `D` split, `?` unknown), `conteo` (per group, how many members cast each letter),
`discrepantes` (deputies who departed from their group), `json` (URL of the official vote on
congreso.es), `tm` (topics), and the optional `porque` (each group's stated reason: text, speaker,
Diario de Sesiones reference, date) and `cg`.

## How `v` maps to deputies

`v` is a string with one character per deputy: `S` yes, `N` no, `A` abstention, `X` did not vote, `-` was
not in this vote (not a deputy at the time). Position `i` in `v` is the deputy at index `i` of
`indice.json` → `diputados`, whose rows are
`[name, group, constituency, party, alta, x, y, seat code, baja]`, sorted by group and then name
(upstream `escano/construir.py`, `diputados()` and `votos_compactos()`). Both have 411 entries in this
snapshot; `v` is an empty string in 2 votes that have no per-deputy detail.

`cg` (only when needed) maps a position in `v` to the group that deputy voted from when it differs from
the group in `indice.json` (e.g. deputies who later moved to the Grupo Mixto).

`x`, `y` and seat code in `indice.json` come from `hemiciclo.json`; deputies no longer in the chamber
have no seat code and take the position of the seat they used to occupy. `diputados.json` adds the
biography and `baja` date by name.

Example: in vote `2-1` (2023-09-19), index 215 is `Castilla Álvarez, María Carmen` (PSOE) and `v[215]`
is `A`, matching her listing in `discrepantes`.

## Session record

`id` (the Diario de Sesiones name, e.g. `DSCD-15-PL-1`; `votos-YYYY-MM-DD` for a Pleno with votes but
no Diario published, 3 in this snapshot), `fecha`, `organo` (`Pleno` or the committee, whose name
carries an upstream parsing artefact, e.g. `Comisión de Pág. 1 Sanidad`), `sesion`, `ds` (PDF of the
Diario on congreso.es, `null` when there is none), `dsNombre`, `titular`, `resumen`, `momentos`,
`reacciones`, `turnos`, `termometro` (turns and reactions per group) and `puntos`, the agenda items
debated:

- `tipo`, `titulo`, `exp` (expediente number when known), `estado` (`analizado`, `pendiente`, `sin-ds`);
- `itemId`: the agenda-item text as it appears in the Diario;
- `votos`: ids of the votes on that item (`votaciones/*.json` → `id`).

`titular`, `resumen` and `momentos` are written by a language model upstream (`escano/analisis.py`),
not by the Congreso.

## Intervention record

`s` (session `id`), `item` (position in the same month's `items/YYYY-MM.json`), `orador` (surname as
in the Diario), `g` (group code, as in `grupos`), `rol`, `pos` (`a favor`, `en contra`, `abstención`
or absent), `tono`, `int` (intensity 1-5), `temas`, `cita` (verbatim quote), `frase` (one-sentence
summary), `responde` (`sí`, `no`, `parcial`, `no aplica`, for answers to a question) and
`responde_motivo`. `pos`, `tono`, `int`, `temas`, `cita`, `frase`, `responde` and `responde_motivo`
come from a language-model analysis made upstream (the model picks the quote). `d` is the position
of the intervention's long text in upstream `site/datos/iv/<session id>.json`, which is not part of
this snapshot.

## How votes, sessions, items and interventions link

```text
vote.id ──in── session.puntos[].votos          (sesiones/YYYY-MM.json)
session.puntos[].itemId == items[intervention.item]   (items/ and intervenciones/ of the same month)
intervention.s == session.id
```

- **Vote → session and agenda item:** look for the vote `id` in `puntos[].votos` of the sessions of
  the vote's month. Every one of the 2,185 votes appears in at least one point. Upstream links them by
  the same `exp` when both sides have one, and otherwise by title similarity, so a vote can appear
  in more than one point (222 votes; 127 of them in more than one session, e.g. a Pleno whose
  Diario is split). A point without `itemId` (`tipo` `Votaciones`, "Otras votaciones de la
  jornada", or a `votos-…` session) groups votes that match no debated item and has no
  interventions.
- **Agenda item → interventions:** the interventions of that session (`s` equal to the session `id`)
  whose `items[item]` equals the point's `itemId`. All 28,200 interventions resolve to a point of
  their session this way.
- **Vote → interventions:** combine both: vote → point(s) → interventions on that point.
- **Vote reason → session:** in `porque`, each group's `[reason, speaker, session id, date]`; the
  session id is a session `id` (all 7,728 reasons in this snapshot resolve).

`item` is a position in the month's `items` array, so always read `items` and `intervenciones` of the
same month.

## Elections

Province keys are two-digit INE codes (`"01"` Araba/Álava … `"52"` Melilla); names are in
`elecciones/territorios.json` → `provincias[code].n`. Files rewritten by the fetch script list codes
`"10"`–`"52"` before `"01"`–`"09"` (JavaScript key order); look them up by code, never by position.

### `elecciones/resultados-2023.json`: 2023 results per province

`id` (`"202307"`) and `fecha` (`"2023-07-23"`) from upstream `data/elecciones/historico-202307.json`,
and `prov`, one record per province taken unchanged from upstream
`data/elecciones/provincias/NN.json` → `"202307"`. That record is the one in `historico-202307.json`
plus `censo` and `nulos`; `pnpm data:fetch` fails if they differ on any shared field.

- `e`: seats the province elected in 2023 (they add up to 350);
- `censo`: electorate; `validos`: valid votes (candidacies plus blank); `blancos`; `nulos`;
- `c`: one row per candidacy, `[acronym, family, votes, seats won]` (family groups parties across
  elections, e.g. `IZQ` for IU, Podemos and Sumar);
- `sin_escano`: votes for candidacies that won no seat;
- `ultimo`: the last seat, `gana` (who won it), `segundo` (closest candidacy) and `faltan` (votes it
  lacked).

### `elecciones/escanos-2026.json`: seats per province in 2026

The keys `convocatoria`, `votacion`, `decreto`, `escanos`, `escanos_cambian` and `padron` of upstream
`site/datos/elecciones/elecciones.json`, values unchanged:

- `escanos`: seats each province elects on 29 November 2026 (they add up to 350);
- `decreto`: the source, Real Decreto 806/2026, de 5 de octubre (BOE-A-2026-20742);
- `escanos_cambian`: `[code, seats 2023, seats 2026]` where they differ (Cádiz 9 → 8, Madrid 37 → 38);
- `padron`: INE population (2025) per province that the allocation is based on.

**Verified** on 2026-10-20 against the annex of
[BOE-A-2026-20742](https://www.boe.es/diario_boe/txt.php?id=BOE-A-2026-20742): all 52
circunscripciones match, 350 seats in total.

`territorios.json` → `provincias[code].esc` is the **2023** allocation; use `escanos-2026.json` for
2026.
